# Flash-Next PP4/TP4 prefill activation localization

`GRIMOIRE_QFN_ACT_DIR` enables the diagnostic only for ranked, in-order `prefill_qwen4_exp`, with MTP off. Set it to a new directory per layout. Each rank writes `r<RANK>-p<CHUNK_START>.bin`. Each record is a seven-field little-endian `uint32` header (`0x31414651`, tap, global layer, rank, absolute position of first row, row count, width), immediately followed by row-major FP32 values. A row's absolute position is `start + row_index`.

The baseline writes embedding residuals before layer 0, then each layer's entry and exit. For a deferred combine, it uses the existing HC combine kernel in scratch, after the producing operation (including TP reduction) and without modifying the live residual. PP writes only its owned layers; TP writes all layers on all ranks. The full six-chunk baseline takes about 54 GB of disk; use NVMe storage rather than `/tmp` on haxor.

`GRIMOIRE_QFN_ACT_LAYER=LAYER` restricts the dump to one layer and additionally records its attention/DeltaNet output and MoE output after reductions. On the PLE layer it also records the post-reduction PLE table input and the residual after injection. These captures synchronize the device queue; neither replay qualifies throughput.

`bin/qfn_compare_prefill_activations RUN_DIR [--layer N]` reads the two layout subdirectories `pp4` and `tp4`. It validates coverage for the six frozen chunks, compares each row on all TP4 ranks against the PP4 owner, and reports the first nonzero and first material differences, ordered by layer, tap, absolute position, and TP rank. Defaults: material if RMS delta is at least `1e-4` and at least 1% of PP4's RMS; both are configurable. The scanner does not infer a cause from a difference.

For the paired diagnostic, build a `spir64` JIT CLI in this worktree, not the serving binary. Use `benchmarks/qfn/qualify_pp4.sh` with `QFN_CASES=matched`, `QFN_MATCHED_OUTPUT=1`, `QFN_PP_CHUNK=512`, `GRIMOIRE_PREFILL_CHUNK=512`, `GRIMOIRE_PP_CHUNK_FIRST=0`, `GRIMOIRE_PP_EVEN=0`, `GRIMOIRE_PREFIX_CACHE=0`, `SYCL_CACHE_PERSISTENT=0`, and a finite `QFN_GPU_TIMEOUT`. Run it once with each `QFN_PARALLEL=pp4` and `QFN_PARALLEL=tp4` with the same JIT image and frozen prompt. The runner takes the GPU lock and forces the same non-XMX MoE mode in both layouts. `GRIMOIRE_QFN_LOGITS_AT_POS=2706` records the final prefill logits for comparison with the uninstrumented parity run.

For one-row MoE localization, set `GRIMOIRE_QFN_MOE_ROW_DIR`, `GRIMOIRE_QFN_MOE_ROW_LAYER`, and `GRIMOIRE_QFN_MOE_ROW_POS`. The reader expects the frozen Flash-Next geometry. The probe records the FP32 MoE input, logits and weights; int32 global and remapped IDs; and FP32 routed, shared, local and reduced outputs. Individual contributions reuse the live gate-up product and expert weight, masking the other slots in a second invocation of the same down kernel. Each owned expert's file is named by global ID. `GRIMOIRE_QFN_MOE_ROW_INPUT` replaces only the selected input row, without changing the enclosing prefill batch size, before running the production router and experts. `bin/qfn_compare_moe_row` expects `native/{pp4,tp4}` and `common/{pp4,tp4}`. It uses the difference of the 10th and 11th logits (not the difference of the two highest logits) to report the routing cutoff margin.

`GRIMOIRE_QFN_MOE_ROW_ENTRY` supplies the full combined layer-entry batch before PLE; each layout still runs its own production PLE injection. `GRIMOIRE_QFN_MOE_ROW_STOP` makes the diagnostic CLI stop after writing the router decisions instead of continuing through the remaining layers or decoding. `bin/qfn_compare_dn_prefix` checks the first chunk and reports the first differing tap.

Build the host-only C++17 tools with `make qfn-tools`; run their CPU regressions with `make test-qfn`. No Python, NumPy, PyTorch, or GPU toolkit is needed for these readers or regressions.
