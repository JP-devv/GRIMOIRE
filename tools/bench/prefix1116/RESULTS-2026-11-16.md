## What changed (commits on longctx-1115 after main f7e12ac)

- `ad6b342` prompt-head snapshots: per slot, the recurrent state (DeltaNet + conv ring) 64 tokens before the end of a
  long prompt, taken while the prompt is read; `prefix_reuse` considers it; restoring it invalidates the slot's
  prompt+reply snapshot; `clear_seq_slot` drops it; under TP the save outcome is agreed.
- `015cacb` TP: agree whenever ranked (the start-up warm-up runs generate on rank 0 before its scheduler exists --
  deadlock otherwise); split point on a 64-token boundary.
- `13a2ea1` a restore keeps the MTP head's cache (prefill fills it; per-slot): decode after a hit 114 -> 127 tok/s at 2K.
- `f444f20` cache ON by default (`GRIMOIRE_PREFIX_CACHE=0` = off); heads only in grimoire-server
  (`GRIMOIRE_PREFIX_HEAD`), so the CLI's answers do not move.
- `6dcbacc` key-major K cache never reaches `launch_flash_decode_batched` (exact verify threw since 11-15).
- Earlier on the branch: verify team kernel at >= 32K, copy verifies as 8-row team pieces, prompt K/V packs.

## Open

- Decode after a repeated 26K prompt 115 tok/s vs 137 without the hit (tokens/step 4.83 -> 3.2-4.0); not explained.
- A first answer to a long served prompt can differ in late words with the cache on vs off (two prompt calls).
- The interleaved admission path (`admit_begin` / `admit_chunk`) does not take prompt heads.
- Snapshots are allocated lazily, outside the load-time VRAM budget (~157 MB per slot per copy on one card for 27B).
