# Grimoire catch-up plan: Qwen3.8-Flash-Next on 4× Arc Pro B70

**Goal:** match the deployed vLLM lane on the same work, then beat it. The first engineering targets are **140 output tok/s at C1** and **4,000 cold prompt tok/s**. These are performance targets, not predictions or reasons to relax correctness. The archived lane averaged 130.7 output tok/s across eight category medians (107–153 range) and measured 4,099–4,556 cold prompt tok/s. The cutover comparison is a fresh paired run, not those headlines.

Keep the engine C++/SYCL and Level Zero, targeting Battlemage G31. The vLLM hot path already calls tuned native XPU kernels. Replacing Python alone does not recover the gap. Grimoire's opportunity is to specialize across operator boundaries: choose and pack layouts at load time, reuse weights across verification rows, preserve device residency, and remove intermediate writes and waits. Use vLLM's installed build as the performance reference and its source to understand layouts and dispatch; do not introduce PyTorch, Python, or vLLM as compute-path dependencies.

## 3. Decode track: a native small-batch verifier

**Budget:** 140 tok/s at 2.95 emitted tokens/round needs **≤21.1 ms for the entire round**; at 2.31 it needs **≤16.5 ms**. Count emitted tokens, not just accepted proposals. The older native diagnostic accepted 21/33 proposals, yet fell from 45.4 to 28.5 tok/s. Its fenced round was ~97 ms (~4.3 ms draft, ~92 ms inside verification, plus snapshot/commit). The later build attempts produced no new verifier timings. Do not assume the 92 ms is entirely target compute.

1. **Recover a buildable verifier on the current stack.** Pin the tuned object/overlay set and compile a diagnostic without lifting the serving guard. Replay identical proposed rows at M=1/2/4. Split the existing `prefill(candidates, &verified)` timing into target layers, head, rank agreement and draft-cache warming. Inside target layers, measure routed dispatch/projections, HC, the existing multi-row GDN kernel, dense attention and exchanges. Count selected expert bytes, repeated reads, and the slowest rank. Measure first-use separately from steady state. The first artifact is a complete round breakdown and the marginal cost of each extra row.
2. **Batch the sharded vocabulary head.** The current TP4 path explicitly excludes split heads from batched GEMM and uses one GEMV and argmax per candidate row (`src/grimoire.cpp`, near the `vlog` allocation). Prototype a BF16 B70 small-M kernel that loads each weight tile once and reduces to local `(score, token_id)` per row. Batch those candidates into one agreement phase with the existing tie rule. Keep full logits for diagnostics or requests that need them. Compare exact/near-tie behavior and full-round time; don't assume the head is the largest cost before measuring it.
3. **Reuse routed expert weights across candidate rows.** Grouped prompt XMX is gated out by `!verify`. Compare the current small-row fallback, repeated DecodeM8, and a true verifier `M≤4` DPAS path. Build a stable local route list on-device, load each packed INT4 tile/scales once for the rows selecting that expert, and use a low-overhead path for singleton experts. Preserve expert IDs, invalid-slot masking, weight codes, and weighted accumulation. Measure expert overlap as well as gate/up, SwiGLU, down and gather together. Keep the M=1 path fast; padding four rows into a large prefill tile is a control, not the goal.
4. **Reduce wasted draft maintenance.** `mtp4_warm_row` loops over candidate rows inside the timed verifier, before acceptance. Compare separate timing first. Then test a batched warm path or moving avoidable rejected-row work after agreement, only if the draft cache and next-round acceptance remain equivalent. If the cycle still misses the budget, profile native HC/mixer projections and host rendezvous before deciding which subgraph to fuse or capture.
5. **Prove transaction correctness before enabling TP4 serving MTP.** Test full acceptance, rejection at every position, EOS and budget boundaries, then continue with the actual next token. Compare committed recurrent state, convolution history, KV visibility, PLE history, next logits and token IDs with independent target-only replay. The same-batch checkpoint validated recurrent/conv restore on one rejection, but sequential state/logits differed and KV/PLE were not independently gated. Find the first divergent layer/row; document numeric tolerance and near ties instead of using 32 matching IDs as proof. After the single-slot gate, repeat with interleaved slots and cancellation.

**Gates:** a faster trace-off full round with no acceptance regression; then **~100 tok/s at ~30 ms and three emitted tokens** as an intermediate checkpoint; then match the fresh reference on a representative corpus and reach the **140 tok/s** target. If a round is too slow despite high acceptance, optimize work per round. If a fast round still emits too few tokens, compare draft logits and per-position acceptance with the exact deployed draft before increasing K.

## 4. Prefill track: specialize the dense path, tails, and movement

**Budget:** the recent trace-off 2,706-token run takes ~2.53 s; **4,000 tok/s allows 676.5 ms**. The older fenced run partitions ~2.60 s across HC, MoE, GDN, full attention and PLE; ~543 ms of exchange is **inside** those phase times, not an additional bucket. Even deleting it would leave over 2 s in that profile. Plan several large savings, then re-profile the same prompt and longer depths after each change. Do not add projected savings from different binaries or fenced runs.

1. **Replace the dense attention path first.** Instrument `launch_dflash2_block_attention` and its callers in `src/prefill.cpp` / `src/grimoire.cpp`. The large-row dense path stages 16-key tiles in local memory and synchronizes per tile. A/B the existing `launch_flash_prefill` XMX path for **6 local Q heads, 1 KV head, head width 256**, with the current E4M3 cache and identical causal ends. Time **cache preparation plus the kernel**, not just the inner loop. If repacking dominates, prototype a G31 DPAS kernel with packed K/V tile reuse across the six query heads and online softmax. Validate bottom-right causal masking on a suffix chunk, one-token and irregular tails, and the first decode token after prefill. Compare the whole attention stage to the deployed vLLM worker's FlashAttention path; keep QSA a separate checkpoint project.
2. **Fix the short-chunk fallback in routed MoE.** In the fenced profile, the 658-row tail spent ~378 ms in routed device work versus ~144 ms on 2,048 rows. The Xe2 tail gate/up and down worked separately on one GPU; TP4 integration faulted. Isolate one projection at a time on all four ranks, validate route offsets and scratch bounds/lifetime across the collective, and compare routed output to an independent replay. After parity, select by live rows per expert and occupancy, not total capacity or `MR == 2048`. Compare m32 to other policies with real route histograms, including skew and zero-route ranks. Measure route packing/readback, SwiGLU, weighted gather and projections together; remove a host readback only if its savings survive the full stage.
3. **Close the same-precision HC and GDN projection gaps.** Keep working HC tiling/fusion. Time actual BF16 shapes, layout conversions and epilogues against the worker trace. Test lossless load-time packing and aligned XMX layouts instead of per-call weight rearrangement; charge the added resident memory. For HC down, use the vLLM K-split implementation as a reference, not permission to ship the native split-K experiment that failed greedy parity. For GDN, measure QKV and Z/out projections separately from convolution and recurrence; optimize the largest remaining part. Fuse only when it removes a real intermediate write or launch and preserves dependency and numerical order.
4. **Cut bytes for large collectives; keep decode separate.** The existing ranked decode path has 97 dependency-ordered reductions per step. In the fenced decode profile actual exchange was ~3.86 ms, and another ~7.49 ms was queued compute draining. A new copy queue doesn't erase either category by itself. For large prefill payloads, compare peer-push, qualified oneCCL and a native Level Zero reduce-scatter/all-gather: send each partial slice to its owner, fold in the canonical FP32 rank order, and distribute the result. This halves ideal payload per rank vs full fan-out; runtime improvement is a hypothesis. Measure bytes, peer arrival, copy completion and mixed compute/copy occupancy on the actual topology. The Gen4 switch and peer read/write capability don't prove a direct payload route; use a forced-host control. Don't assume peer atomics or revive the IPC event path without new parity and fault/drain gates. Test smaller wire precision only as a separate numerics arm.

**B70 implementation contract:** G31 AOT for promoted kernels; experiment with DPAS/XMX tile shape, GRF use, spills, ESIMD block loads and local-memory occupancy on captured production layouts. Keep packed quant codes, scales and zeros unchanged unless a separate precision experiment is approved. Use stable, bounded scratch and explicit dependencies. Compare the complete operator path (layout, kernel, output and wait), then trace-off prompt time. A faster microbenchmark that leaves end-to-end time flat is not a promotion.

## 5. Integration, milestones, and cutover

| Checkpoint | Deliverable and decision |
|---|---|
| **Baseline pinned** | Exact native build receipt, same-prompt target-only comparison, actual backend proved in every timed arm, and a current four-row diagnostic. In parallel, capture the matched vLLM worker trace and the first dense XMX attention A/B. |
| **Large costs removed** | At least one verifier replacement improves the full round without reducing acceptance; dense attention and uneven MoE changes pass continuation and improve full prompts. Re-measure the remaining gap in milliseconds; prioritize the next biggest complete stage, not the most interesting kernel. |
| **C1 and cold-prefill parity** | Match the fresh deployed reference on the matched corpus and cold depth curve. Report 140 tg and 4,000 pp separately, with actual tokens/round, TTFT, stream gaps, quality and failure counts. Test long output and uneven chunks so a narrow fixture can't carry the claim. |
| **Cutover qualification** | Match or beat served C4/C8, warm multi-turn and mixed prompt/decode load. Validate requested context capacity, multi-slot isolation, long-context outputs, cancellation, first long request after startup, and sustained operation. Text throughput is not qualification for vision/tool/API parity. Keep the vLLM rollback image and config intact. |
| **Beyond parity** | Prioritize hybrid prefix reuse, decode-first scheduling with bounded prompt slices, and K8/V4 where quality and latency/capacity tests justify it. Compare native subgraph capture only after tracing launch gaps and qualifying stable buffers. Test expert redistribution only if measured rank skew remains material. These are not prerequisites for the first dense text speed experiments or substitutes for the separate gates in [proposition.md](proposition.md). |

**Start here:** preserve the candidate, fix timed-arm dispatch assertions, restore the current-stack verifier replay, and run the dense XMX attention A/B. Do the matched vLLM worker trace alongside those changes. No vLLM rebase, QSA rewrite, precision switch, or production cutover in the first pass.
