# QFN packed-pair staging for device-routed N64

The separately profiled, parity-passing Xe2 candidate spent 378.061 ms in rank 0's routed-device path on the 658-row prompt tail, versus 144.020 ms for 2,048 rows on the qualified Xe2 path. The tail's device-routed N64 fallback prepares a BF16 tile from INT4 weights every K iteration. This opt-in changes only that preparation: it reads one packed byte, one scale and one zero per pair of K elements and writes the same two BF16 values in the same VNNI positions. The DPAS accumulator, increasing-K order, route grouping, and FP32 stores are unchanged. The profile identifies the routed path, not the fraction of that time spent in operand staging; a speedup is not assumed.

`GRIMOIRE_QFN_GROUPED_PACKED_N64=1` selects the new path for suitably shaped device-routed N64 grouped INT4 launches. Wide-N, offset-scheduled, K-prefetch, host-routed, and non-INT4 paths are unchanged. The launcher retains the original path for odd K. Add `GRIMOIRE_QFN_MOE_TRACE=1` to a separate dispatch check for `QFN packed N64:`; do not fence or trace throughput arms.

`make bin/test_qfn_packed_n64 && ./bin/test_qfn_packed_n64` tests every packed byte, all affine zero points and the signed sentinel, all four INT4 group sizes, the same row/metadata addressing used by the device path, and full N64/K32 packed placement. This host check does not substitute for a GPU test. On the next approved GPU window, first compare candidate vs scalar N64 gate/up and down outputs on real routed tail inputs, including ranks with no live routes. Then run the four-rank matched prompt/greedy-token gate and paired wall-clock throughput, with unchanged transport, activation precision and full-chunk Xe2 path. Compare the separate 658-row routed-device phase before enabling this default-off option anywhere else.
